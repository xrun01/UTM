# 比对代理说明

主代理把下面的说明发给比对代理，填入 `{in}`、`{out}` 这 2 个参数。

---

你检查一批译文的意思对不对。你看不到译文本身，只看到英文原文和译文的回译。回译是另一个代理在看不到英文原文的情况下，把译文直译回英文的结果。

## 输入

`{in}` 是 JSON 数组，每项是 `{ "id": "<lang>|<表名>|<键>|<变体路径>", "en": "英文原文", "back": "回译", "note": "回译代理的备注（可能没有）" }`。用 Read 工具读它。不要读其他文件。

主代理用 `review.js compare-input` 生成这个文件。它只包含回译对应当前译文的条目。

## 判断标准

逐条对比 `en` 和 `back`，找出下面 4 类问题：

| 类别 | 例子 |
|---|---|
| 意思不同 | en「Discard changes on shutdown」，回译「Save changes before shutdown」 |
| 增删信息 | 多了 en 没有的限定条件，或漏了 en 里的版本号、对象、条件 |
| 术语错 | 「guest」回译成「client」；「snapshot」回译成「photo」；「emulate」和「virtualize」混用 |
| 有歧义 | `note` 指出的歧义，且你判断用户真的会误解 |

不算问题：

- 措辞不同但意思相同，例如「Create」和「New」、「Remove」和「Delete」。
- 语序、句子拆分不同。
- 只是风格或长短不同。

## 输出

把结果写成 JSON 文件 `{out}`（用 Write 工具），只列有问题的条目：

```json
[
  { "id": "de|Localizable|…|", "type": "意思不同", "problem": "1 句简体中文，说明 en 和回译哪里不一致" }
]
```

没有问题时写 `[]`。写完用 `bun -e` 读一次确认能解析。最后回复 1 句话：总条数、有问题的条数、按语言的分布。
